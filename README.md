# 青禾种质站 · 复壮与授粉隔离

青禾种质站有8位育种员、18块隔离小区，保管青豆原种质。过去种子出入库记在种袋纸签上，活力复测在另一张表里，田间花期靠手绘日历安排：复测抽样经常漏扣粒数；A1/A2两块田虽未重复占地，邻接青豆花粉仍可能串入；收获后把旧种袋改个年份，会丢失亲本与代次。这里从入藏、发芽复测开始，到隔离复壮、收获下一代、共享保底形成一条可追溯业务链。上游是采集签、发芽纸计数、袋签和田间记录；下游是保种库管、授粉主管与协作育种圃。

六个可操作页面：种质与复测、复壮领种、隔离花期、亲本套袋、收获谱系、共享保底。Python FastAPI + 原生HTML/CSS/JS ES modules；MySQL8 READ COMMITTED、Redis队列、独立Python worker、Nginx组成恰好五服务。

## 六个模块与规则

1. **种质入库与活力复测**：Accession种质号唯一，作物/身份/最低保底不可覆盖，主管可修名称与采集来源备注。Lot有亲本批、代次、粒数、储期、储温和初始发芽率；首批仅允许尚无种批的新种质手工入库，已有种质新增代次必须走收获，不能用新增批绕过库存约束。GerminationTest抽20–1000粒，发芽数≤抽样数；实际抽样立刻耗种，也检查保底。
2. **复壮触发与种子领用**：复测由worker完成活力估计，实测或预测<85%才允许复壮；申请保存当时活力快照。requested→主管issue实际扣种→issued。仅未分配地块的requested/issued可主管cancel，已扣粒数返还一次；已下田不能直接取消退种。
3. **隔离地块与花期冲突**：18个小区A1–C6，正交相邻一格算邻接。同地块任何作物花期重叠都拒；邻接同作物也拒，日期首尾均包含。先已领种，且粒数≤地块250株容量，才可编计划。planned→主管assigned；冲突不改状态，修改planned的日期后再核准。主管锁全部18地块，再查询占用，避免两个相邻地块并发同时成功。此串行范围适合小站，不用于大规模地理调度。
4. **授粉袋与亲本配对**：Pollination每复壮单唯一，袋签全局唯一。必须已有assigned隔离安排；母本就是领种批，父本同种质同代次；花数≤领种株数。未套袋可保存prepared但不能pollinate，补套袋后恢复。主管授粉后亲本、袋签与花数不可改。本项目做原种质复壮，不受理异源杂交。
5. **收获回库和代次继承**：授粉后登记净收粒数与含水。drying可复测修改，含水≤12%主管store；一复壮单一收获，创建母本generation+1的独立后代Lot，冻结当时母父本、袋签、花期、活力快照；同时复壮harvested、地块released。后代initial_rate仅继承为计划先验，后代共享前必须独立发芽复测，不能当成新批质量认证。
6. **共享申领与保底量**：申请含接收单位、用途与粒数。主管approve前要求该批独立复测完成且实测≥80%；实际扣种，写签发前后总量/保底/复测快照。requested→approved→operator登记received，不重复扣种或签收。全种质所有种批合计不能低于最低保底，抽样、复壮领种、共享签发共用Accession父行锁，READ COMMITTED保证等锁后SUM看到前事务提交的新余额。

所有失败事务回滚，不更改余额、已冻结亲缘或已签发状态。数据库唯一键约束种质号/批号/复测号/复壮号/袋签/收获号/共享号及每复壮单单一花期、授粉、收获。已有历史种批不覆盖或回填。

## 活力模型与可复现口径

`backend/src/vitality.py`用固定Random32生成180条模拟储藏观测：储期0–60月、温度−18至22℃、初始发芽率80–98%，目标为初始率−0.29×储期−0.34×(温度+18)+高斯噪声，再裁到0–100%。数据不是实际客户种质或实测农业试验。

先固定seed32拆135训练/45留出，StandardScaler只fit训练，BayesianRidge只fit训练目标。留出计算MAE（百分点）与预测均值±1.96×predictive std的95%区间覆盖率。新种批输入储期/温度/初始率，输出均值、95%预测区间、实测发芽率、是否触发85%规则；区间展示裁到0–100。样本序号、训练/留出索引、源数据SHA256和输入快照持久化。区间依赖合成线性高斯假设，不承诺实际覆盖或农业有效性。

`POST /germination-tests/{id}/estimate`将recorded/failed送Redis；worker取队列后置running，计算真实sklearn结果，写MySQL prediction与共享卷`/artifacts/vitality-<id>.json`。失败保存error，恢复后可重新排队。worker心跳支持健康检查。未实现worker硬崩溃后自动回收running任务；此时需运维恢复队列/状态，不虚称可靠投递。

## 一天的复壮剧本

1. 08:30 查看`QH-021`青豆、G3主批960粒、同代授粉批400粒与保底300粒，核对北圃2023采集签；A1/A2是相邻地块。
2. 09:00 检查历史`GT-SEED-80`复测80/100粒（这是已归档计数，seed不再次扣种）。新增复测如`GT-20261118-01`会扣100粒。点击“送交活力估计”，查看135/45样本和区间证据。
3. 09:20 以低于85%的复测创建`RG-QH021-01`领种120粒，主管签发，剩余种子真实减少120；超保底量被拒，不改余额。
4. 10:00 将复壮单排到A1，2026-11-20至25日开花；另单排A2相同日期主管核准被拒，改为11月26至30日恢复。日期均是业务计划值，不依赖运行当天时钟，演练不会过期。
5. 10:30 登记母本`QH-021-G3`、父本`QH-021-POLLEN`、袋签`BAG-QH021-01`、40花。未套袋授粉被拒，补封口检查后主管确认；异源`QH-087-G2`父本不接受。
6. 14:00 录收获`HV-QH021-01`1800粒，含水15%暂不能回库；干燥复测10.5%后主管回库，得到`HV-QH021-01-G4`，母本代次3→4，谱系保留。
7. 15:00 G4新批抽100粒、发芽90粒，独立估计后申请共享200粒给“青禾协作育种圃”，用途性状复核，主管核保底后签发。
8. 16:00 协作接收记录留本地回执；观察员复看代次、袋签和签发时余额，不向外发送消息或运输指令。

## 源码组织与开发

后端`models.py`独立关系表；`schemas.py`请求约束；`common.py`父锁/余额/审计；`renewal_service.py`抽样/活力触发/领退种；`isolation_service.py`地块花期/亲本授粉；`harvest_service.py`代次回库；`sharing_service.py`保底签发；`main.py`逐路由权限/提交；`worker.py`真实计算。READ COMMITTED在db.py；所有SUM先锁父种质。

前端六个`src/pages/*.js`各自有真实表单/状态动作。`components/specimens.js`至少三种业务组件：种批标本签、保底条、花期带，跨复测/复壮/回库/共享复用；`utils/format.js`转义与表单类型，`utils/actions.js`写请求与通知；`store.js`从archive取关联实体。前后端`constants`定义角色、复壮、花期、授粉状态，实际状态字段/路由由服务规则执行。

本地backend安装requirements后设置DATABASE_URL/REDIS_URL/JWT_SECRET，运行`uvicorn src.main:app --reload`，另一进程`python -m src.worker`；前端建议保留Compose Nginx代理。seed按自然键只补缺，不覆盖人工名称来源、粒数、复测、花期、谱系和回执；重复seed不重扣历史样本、不回填已签记录。演示证据与测试在`../../test-artifacts/gb-1032/`，不混入源码。

局限：简化18格正交邻接，不模型风向、作物隔离距离、真实授粉日期/袋材消耗；粒数按整数株数计划，不模拟出苗率到单株映射；无硬件读数、照片上传、电子签章或外部共享接口；批次储期不会随系统时钟自动老化；演示口令/固定JWT需部署时替换。仅合成数据辅助与业务记录，非农业生产建议。
